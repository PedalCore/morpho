# M5 — objective-derived fast-weight associative memory (formalization
# before training; adopted 2026-08-24)

DECISION: CRSA + slots is FROZEN as a successful constant-state result
(6.48; binding 0.94 under supervision; full ledger in M4.md). The next
architecture is an implicit online-regression memory — retrieval as
the stated objective — not another counter variant.

## The operator

Each layer maintains a fast-weight matrix S_t (per head, p_k x p_v)
that is the solution of an online ridge regression "given this key,
what value belongs to it?":

  S_t = argmin_S  1/2 ||S k_t - v_t||^2 + 1/(2 b_t) ||S - g_t S_{t-1}||_F^2

Exact closed-form update (delta rule with decay g and write strength b):

  S_t = g_t S_{t-1} + (b_t / (1 + b_t ||k_t||^2)) (v_t - g_t S_{t-1} k_t) k_t^T

Read: y_t = S_t q_t. The residual e_t = v_t - S_{t-1} k_t is the
error-driven write criterion — the principled replacement for slots
guessing what deserves storage. Family: delta-rule / Longhorn
(implicit online regression; Mamba-class training speed) / Gated
DeltaNet (targeted correction + erasure, chunkwise-parallel). Design
decisions inherited FROM M4's measurements: separate query map (the
binding bottleneck; low-rank later), the k=4 causal conv as local
write-association assembler, MLP feature block first (cleanest
control) with the dictionary prox restored in arm E.

## The have-your-cake construction (arm D)

Dense delta state interferes once unrelated associations collide —
fundamental for fixed-size recall (Zoology: associative-recall tokens
= 82% of the recurrent-vs-attention gap). Remedy: delta state for
compressible history + a SMALL BOUNDED EXACT STORE admitting only
high-residual "surprises" (write when ||e_t|| exceeds a calibrated
threshold; bounded slots, LRU/decay eviction). Semiparametric
precedent: HOLA (2025-26 preprint, single-paper, replication owed);
aggressive frontier (NOT first): sparse delta memory via product-key
addressing.

2. SPEED: >= 2x faster than the current slots implementation per step,

   before any training; published CUDA/Triton speedups do not
   transfer to MPS automatically; if the scan is not efficient here,
   STOP before any 20k run.
3. LANGUAGE: within ~0.3-0.5 ppl of QKV at a matched checkpoint
   before earning a long run.

## Explicitly deprioritized

Another scalar-counter variant (understood: strength and ceiling);
pure Mamba/RWKV as the contribution (controls, not novelty — recall
is their weak point too); TTT-MLP first (expressive, memory-I/O
heavy); interleaved full-attention layers (safe product, weak
science); immediate silicon hardening (earn the operator first).
Mamba-2's lesson: choose a recurrence admitting an efficient
associative scan AND implement the scan properly — the speedup is as
much kernel as architecture.


## Gate 2, first measurement — SEQUENTIAL FORM FAILS AT LM SCALE

The exact sequential delta (256-token python loop, 12 layers, MPS,
fwd+bwd, batch 16) did not complete a 6-step benchmark inside 10
minutes: >> 100x too slow. Per the preregistered rule ("if the scan is
not efficient here, STOP before any 20k run"): NO LM training with the
sequential form. Correctness verified at small scale (causal pre-diff
0). The required engineering before arm B runs at LM scale: a
chunkwise-parallel exact delta (WY representation / DeltaNet-style —
intra-chunk matmul form, inter-chunk recurrence), verified for forward
AND gradient equivalence against the sequential reference. Probe-scale
(d=128) feasibility to be measured separately — the M5 capability
ladder may proceed on probes while the kernel work happens.

## POSITIONING CORRECTION (2026-08-24, on reading Longhorn 2407.14207)

Longhorn derives the recurrent mixer from ESSENTIALLY THE SAME
proximal online-regression objective (their eqs. 5-6): "derive a
sequence mixer from implicit online associative regression" is
LONGHORN'S contribution, not M5's novelty. M5-implicit is hereby
repositioned as: a FULL-MATRIX, EXPLICITLY-DECAYED extension and
diagnostic comparison to Longhorn — not a novel derivation.

THE KEY DIFFERENCE, and the sharpened (potentially publishable)
question: Longhorn derives the full correction (I - eps k k^T) but
IMPLEMENTS the diagonal approximation (1 - eps k^{o2}) because
rank-one-product recurrences resist parallelization while diagonal
recurrences scan efficiently. That approximation is exactly why our
exact sequential form was catastrophically slow — we kept what
Longhorn diagonalized away. QUESTION: does Longhorn's diagonalization
preserve the associative computation implied by its own exact
objective — and if not, can the exact update be parallelized without
surrendering binding? This fits the campaign's method precisely:
locate where a published derivation becomes an approximation, measure
what the approximation costs (with instruments — counterbalanced
binding, selective recall, capacity — that published evals lack;
Longhorn reports strong MQAR and Mamba-competitive LM at 120M-1.3B,
so it is a serious architecture, not adjacent theory).

THE DECISIVE THREE-ARM COMPARISON (matched projections/params/seed/
probe training):
| arm | update | meaning |
|---|---|---|
| M5-exact (running) | full I - eps kk^T + decay | derivation-faithful, slow |
| M5-Longhorn | diagonal 1 - eps k^2 | fast published approximation |
| M5-GDN | gated delta (FLA) | optimized retrieval baseline (GPU-gated) |

Outcome map (recorded in advance): diagonal matches exact on binding
=> use Longhorn's kernel, abandon bespoke exact parallelization;
exact binds where diagonal fails/loses capacity => the approximation's
cost is identified and exact chunkwise parallelization becomes
scientifically justified; GDN matches/wins => learned erasure matters
more than proximal exactness; all pass => choose by LM ppl+throughput.


## Early results + LM-scale reality for the diagonal

M5-implicit (exact, running): **binding 0.991 at step 4,000** (loss
0.002) — the retrieval-derived operator matches full-QKV's trajectory
at constant state, no oracle/slots/routing. Mid-run read; locked grid
at final; 819k-param caveat (largest probe arm).

M5-Longhorn implemented (diagonal 1 - eps k^2, chunked varying-decay
scan, equivalence 1.2e-6 vs sequential diagonal reference, causal).
Probe-scale 0.38 s/step (2.1 h/arm) — queued behind the exact arm.
LM-SCALE HONESTY: even the diagonal form fails LM-scale on MPS in
naive PyTorch — the chunked scan still MATERIALIZES the p x p state
stream (~400 MB/layer before autograd); diagonalization fixes
parallelizability, only a fused kernel fixes materialization. LM-scale
M5 remains GPU-gated FOR BOTH ARMS.
