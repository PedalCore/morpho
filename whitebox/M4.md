# M4 — memory binding and retrieval (formalization before training)

The probes and generations localize CRSA's failure precisely: forgetting
by COLLISION, not by time — perfect induction at every delay, weak
selective retention under distractors (0.56 vs 0.91), name drift in
generated stories. M4 is the repair program. Three problems at three
different stages of the block; they are NOT one problem:

| problem | stage | repair |
|---|---|---|
| insufficient nonlinear capacity | feature extraction | active overcomplete dictionary — **already substantially repaired** (8.40 vs 9.72) |
| entity collisions | writing history | separate information into keyed slots/statistics |
| weak selective retrieval | reading history | make the read depend on the current query |

## Why the counters collide

c_t = rho c_{t-1} + h_t^2. Squaring discards SIGN; summation discards
OWNERSHIP. If Tom and Tim activate overlapping coordinates, their energy
enters the same counters: the model knows an entity-like feature was
recently active, but not which entity owned which attributes. Write
collision (entities share statistics) and read ambiguity (no query can
ask for "Tom's information") are linked but distinct. Longer contexts
can WORSEN this — more entities through the same fixed statistics.

## The ladder (in order; one change per rung; zero-init contract)

Every new mechanism enters as a ZERO-INITIALIZED residual on the trained
parent (beta = 0 / gamma = 0 reproduces the parent exactly — verified
numerically at implementation time, 0.00 diff on the parent checkpoint).
No conversion shock; warm-start via strict=False.

**Rung 1 — signed moments (cheapest information-loss ablation).**
s_t = rho s_{t-1} + h_t alongside c_t; read dcoef*(h + beta*s).
State 448 -> 896 values/layer; +12 scalar params. Restores the sign
information h^2 destroys. Will NOT solve binding (Tom and Tim still
superpose); measures how much of the failure is the squaring loss alone.

**Rung 2 — local-cache retrieval ORACLE (diagnostic, not a design).**
y = y_CRSA + gamma * y_local, exact softmax attention over the last
W = 16 tokens only. State 2Wd = 14,336 values/layer (a W-token ring) —
fixed in total context length but much larger than 448 counters, and no
longer counters-only. Interpretation map:
- distractor recall + names + ppl improve => selective retrieval is the
  missing mechanism (proceed to rung 3);
- no improvement => problem is upstream feature representation;
- only recent references improve => cache fixes locality, not long-term
  entity memory.

**Rung 3 — sparse representative memory (the derived repair).**
M content-addressable statistical slots per layer. Sparse router
a_t = prox(q_t^T K) assigns each event to 1-2 representatives; each slot
keeps decaying statistics N_j = rho_j N_j + a_j, V_j = rho_j V_j + a_j v_t;
the read is r_t = sum_j pi_j(q_t) V_j / (N_j + eps). Tom routes to one
slot, the red ball to another; attributes accumulate separately; a
Tom-query reads Tom's slot, not the global mixture. Router as binary/WTA
prox with a fixed access-energy penalty — objective-derived,
spike-compatible, fixed work per token. State M d = 3,584 (values only)
or 2Md = 7,168 (dynamic keys) per layer at M = 8 — fixed whether the
sequence has 100 or 100,000 events. Implement ONLY if the oracle fires.

**Dictionary extensions (two ISTA steps, group-sparse atoms, larger q,
split key/value dictionaries): NOT NOW.** The factorial and the 20k run
say the feature block works; probes point at binding/retrieval.

## The probe-first evaluation ladder (collaborator protocol, adopted)

No 20k TinyStories run per repair. Tiny models (d=128, L=4, ctx=128,
matched budgets, the locked optimizer recipe) against five arms: CRSA |
signed counters | CRSA + local cache | CRSA + representative slots |
full KV as ceiling. Ladder: tiny synthetic probes (3 seeds preferred)
-> only passing mechanisms get a 3,000-step TinyStories screen -> only
screens with improved retrieval AND credible ppl trajectory get a long
run -> generation samples LAST, as qualitative confirmation. The
nonlinear-capacity question needs no new synthetic campaign (the
factorial closed it); these probes focus narrowly on binding collisions
and selective retrieval.

## The binding-swap probe (m4_probes.py — the sharp new instrument)

Matched twin pairs: STORE k1 v1 ... kF vF, identical names, attributes,
gap and distractor positions; ONLY the pairing permutation differs, and
the query targets a swapped position so the twins' answers must differ.
A marginal-statistics memory sees nearly the same evidence in both; a
binding-capable memory must separate them. Names/attributes randomized
every example. Axes swept INDEPENDENTLY to separate failure modes:

| sweep | held fixed | falling accuracy means |
|---|---|---|
| delay 8..96 (NULL fillers: pure time) | 2 facts | temporal forgetting |
| facts 2..16 | gap 16 | interference / collision |
| distractors 0..64 FILL (total gap fixed at 64) | 4 facts | weak selective retrieval |
| query gap 8 vs 48 (around W=16) | 4 facts | local-cache benefit vs persistent retrieval |

## Preregistered micro-gates (locked 2026-08-22, before any repair trains)

A repair earns a TinyStories screen ONLY if it:
1. preserves induction near 1.00 on the locked grid;
2. recovers >= half the CRSA-to-KV selective-recall gap:
   0.56 + (0.91-0.56)/2 = **0.735** minimum;
3. improves binding-swap accuracy AS STORED ENTITIES INCREASE
   (the facts sweep — beats parent CRSA at every level, gap growing);
4. beats parent OUTSIDE the cache window if it claims long-term
   retrieval (bind-window@48);
5. stays inside its declared recurrent-state budget
   (sm: 896/layer; cache16: 14,336/layer; slots M=8: 3,584-7,168).

Training distribution note: M4 probe models train on locked tasks +
binding mixed (m4_probes.train_stream) — a DIFFERENT distribution from
the locked M3 runs; arm comparisons are within-protocol, plus the
absolute induction gate.

## Judgment axes (all rungs)

Ordinary 256-token perplexity | selective recall under distractors |
associative recall | controlled name/object consistency | recurrent
state + hardware cost. A rung that buys ppl but explodes state is a
different architecture, not a repair.

## The long-context axes (SEPARATE from binding — three different numbers)

- **T** (training sequence length), **P** (position range), **H**
  (counter horizon) are independent knobs. Practical constraint with a
  learned absolute table: P >= T. P > T costs parameters without
  teaching long dependencies; P < T recreates the clamp defect.
- Position table cost is P x d static params (P=1,024 at d=448: +344k,
  +2.5% on 14M) — no recurrent-state or per-token-complexity change.
  Untrained new entries at inference would HURT; extension requires
  training. Cleanest control: parameter-free sinusoidal features
  (also removes the existing 114,688-param table). For MIDI later:
  elapsed ticks + cyclic beat/bar phase, no absolute position at all.
- Horizon: the ladder m in {3,4,5,6} x2 is mostly short-range. The
  8 heads can be REDISTRIBUTED to m in {3..10} (half-lives ~5 to ~710
  tokens) at the SAME 448 counters and ~same params — reallocating
  counter capacity from short-term detail to long-term history.
- The clean experiment: P=1,024 (or sinusoidal), extend the decay
  ladder, train progressively 256 -> 512 -> 1,024 on GENUINE continuous
  stories (concatenating unrelated stories adds irrelevant history and
  can worsen collisions), judge on ordinary ppl AND distance-conditioned
  entity retention separately — long-context gains may not move 256-tok
  ppl at all. This separates "position 256 was broken" from "the model
  learned longer memory".
- Note: the recurrent sampler (recurrent.py) clamps position beyond ctx
  — counters integrate unboundedly, the positional table does not.

## Expected shape of the result

The likely final architecture: sparse nonlinear features -> multiscale
counters + small sparse representative memory -> query-selective read.
CRSA keeps the efficient global "feel"; a small derived mechanism
remembers exactly who or what produced it.

## REFRAMING (collaborator, 2026-08-22, after the kv chance finding +
## rung-1 fail; before cache16/qkv reported)

The repair target sharpens: the architecture may lack a mechanism that
separates an ADDRESS (key), a LOOKUP QUERY, and the VALUE stored at
that address. CRSA compresses h^2 into statistics; tied MSSA uses ONE
projection for all three roles. Both preserve activity and repeated
patterns; neither necessarily forms arbitrary key->value bindings.
"Collision" may describe TWO different failures:
1. multiple memories compressed into the same state;
2. the model never learned an address->value binding circuit at all.
M4 is now distinguishing those.

Updated interpretation per repair:
| repair | updated reading |
|---|---|
| signed moments | cheap diagnostic for squaring loss; better description, no address book — cannot solve ownership alone |
| more/slower counters | temporal retention, not binding |
| longer positions | irrelevant to fixed-delay binding failure |
| local cache | useful only if its read separately matches keys and returns values |
| dictionary capacity | better features; cannot establish ownership |
| representative slots | strongest repair, MUST have distinct k/q/v roles |
| untied QKV | elevated from ceiling control to possible direct architectural repair |

Representative memory becomes ASYMMETRIC (supersedes the symmetric
rung-3 sketch): q_t = W_q x_t, k_t = W_k x_t, v_t = W_v x_t;
j = route(k_t, K) (binary/WTA prox, constant slots);
V_j = rho V_j + v_t on routed slots; read r_t = sum_j match(q_t, K_j) V_j.
Write-address and read-query are DIFFERENT projections — an actual
associative mechanism at fixed state, no growing cache.

Decision table for the running arms (recorded in advance):
- signed moments pass => squaring was a major culprit. [ALREADY MOOT:
  rung 1 FAILED gate 1 — induction collapsed 1.00 -> 0.55-0.64,
  selective 0.28 -> 0.13, binding lift only +0.04. The beta-read
  interferes destructively with the price-gated read. Verdict:
  screen-DENIED in this form; consistent with "no address book".]
- cache passes only inside 16 tokens => exact recent retrieval works,
  persistent addressing missing => build asymmetric slots.
- untied QKV passes while tied MSSA fails => separate q/k/v roles are
  ESSENTIAL; audit every cache/slot design for that separation.
- representative memory later passes beyond the window => fixed-state
  binding solved.
- untied QKV also fails => stop modifying CRSA; repair the probe
  curriculum/feature block/training setup first.

If QKV passes, the next principled repair is NOT more counter capacity
— it is query-conditioned, asymmetrically written fixed-state memory.
